For tabular health data the story is quieter: trees still win most contests. We will see why, and we will see it in our own data.

1 · What a network is

You already own a neural network

Logistic regression:

\[p = \sigma(w_1 x_1 + \dots + w_p x_p + b), \qquad \sigma(z)=\frac{1}{1+e^{-z}}\]

A neuron (unit): weighted sum → bias → non-linear activation. \(w\) = weights, \(b\) = bias.

That is the whole building block. Everything else is wiring.

Its limit is geometric: \(p \ge 0.5 \iff z \ge 0\), and \(z = 0\) is a straight line (a hyperplane). One neuron draws one straight boundary.

Why one neuron is not enough

  • XOR and the two rings: no \(w_1, w_2, b\) separate them. Logistic regression scores 55 %.
  • Minsky & Papert (1969) made this point and the field stalled for fifteen years.
  • The fix was obvious and un-trainable until backpropagation: let several neurons each draw a soft line, then let one more neuron combine the lines.

The multilayer perceptron

One hidden layer of \(H\) units, one output, one person \(\mathbf{x}\in\mathbb{R}^p\):

\[\begin{aligned} \mathbf{z}^{(1)} &= \mathbf{W}^{(1)\top}\mathbf{x} + \mathbf{b}^{(1)} \\ \mathbf{a}^{(1)} &= g(\mathbf{z}^{(1)}) \\ z^{(2)} &= \mathbf{W}^{(2)\top}\mathbf{a}^{(1)} + b^{(2)} \\ p &= \sigma(z^{(2)}) \end{aligned}\]

\(\mathbf{W}^{(1)}\): \(p\times H\); \(\mathbf{W}^{(2)}\): \(H\) numbers. For \(n\) people, stack \(\mathbf{x}\) as rows of \(\mathbf{X}\) and it is all matrix multiplication → GPUs → five lines of R.

Parameters: \(pH + 2H + 1\). For us (\(p\approx45\), \(H=30\)): 1,411.

“Deep” just means more of the same

\[\mathbf{a}^{(2)} = g\!\left(\mathbf{W}^{(2)\top}\mathbf{a}^{(1)} + \mathbf{b}^{(2)}\right), \qquad \mathbf{a}^{(3)} = g\!\left(\mathbf{W}^{(3)\top}\mathbf{a}^{(2)} + \mathbf{b}^{(3)}\right), \ \dots\]

Each layer re-describes the previous one’s output. Depth lets a network compose simple features into complex ones with far fewer units than one very wide layer would need (edges → textures → parts → objects).

A worked forward pass — keep these numbers

2 inputs → 2 tanh units → 1 sigmoid output. One person, \(\mathbf{x} = (1.0,\ 0.5)\), truly a case (\(y = 1\)).

\[\mathbf{W}^{(1)} = \begin{pmatrix} 0.5 & -0.3 \\ 0.2 & 0.8 \end{pmatrix},\quad \mathbf{b}^{(1)} = (0.1,\ 0.1),\quad \mathbf{W}^{(2)} = (0.7,\ -0.4),\quad b^{(2)} = 0.05\]

Step Computation Result
hidden pre-activations \(1.0(0.5)+0.5(0.2)+0.1\); \(\ 1.0(-0.3)+0.5(0.8)+0.1\) \((0.70,\ 0.20)\)
hidden activations \(\tanh(0.70),\ \tanh(0.20)\) \((0.6044,\ 0.1974)\)
output pre-activation \(0.7(0.6044)-0.4(0.1974)+0.05\) \(0.3941\)
prediction \(\sigma(0.3941)\) \(\mathbf{p = 0.5973}\)

The network says 60 % for someone who is a case. It should say more. Training is how it learns to.

Activation functions: the non-linearity is the point

Formula Derivative Use
sigmoid \(1/(1+e^{-z})\) \(\sigma(1-\sigma)\) binary output; nnet hidden units
tanh — \(1-\tanh^2 z\) zero-centred; our from-scratch net
ReLU \(\max(0,z)\) 1 if \(z>0\) else 0 default hidden unit in deep nets
softmax \(e^{z_k}/\sum_j e^{z_j}\) — multi-class output

Without a non-linear \(g\), layers collapse: a product of matrices is a matrix → one linear model. The squash is what lets eight neurons make a ring.

Saturation: where sigmoid/tanh are flat, the derivative ≈ 0, so earlier layers stop learning — the vanishing gradient. ReLU’s derivative is exactly 1 on the positive side; that is most of why 2012 happened.

2 · How it learns

The loss: what “wrong” means

\[L = -\frac{1}{n}\sum_{i}\Big[y_i\log p_i + (1-y_i)\log(1-p_i)\Big]\]

  • Binary cross-entropy = the negative log-likelihood logistic regression maximises. Nothing new.
  • Punishes confident wrong answers brutally: \(p=0.99\) when \(y=0\) costs 4.6; \(p=0.6\) costs 0.9.
  • Smooth → has a gradient everywhere. Accuracy has no useful gradient, so nothing is trained on it directly.
  • Regression: MSE. Multi-class: categorical cross-entropy. Survival/ordinal/custom: write your own.

For the worked example: \(L = -\log(0.5973) = 0.5154\).

Gradient descent: walk downhill

\[\theta \leftarrow \theta - \eta\,\frac{\partial L}{\partial\theta} \qquad \text{for every weight and bias}\]

  1. Start with small random weights. 2. Compute the loss and its gradient (direction of steepest increase).
  2. Step against it, by the learning rate η. 4. Repeat for many epochs.

Same knob, same trade-off as XGBoost’s learn_rate this morning.

Batches, momentum, Adam

Variant Gradient from Comment
batch GD all \(n\) rows exact; slow for large \(n\) (Tutorial 7 Part B; nnet via BFGS)
stochastic (SGD) one row noisy; the noise helps escape poor regions
mini-batch 32–512 rows the standard; 1 epoch = all batches once (brulee, torch, keras)
momentum running average of past gradients rolls through flat regions, damps zig-zag
Adam / AdamW per-weight adaptive step + momentum default optimiser in most of deep learning
L-BFGS uses curvature excellent for small nets; nnet and brulee’s default

A learning-rate schedule (decay, cyclic) often matters more than which optimiser.

Backpropagation is the chain rule — step 1: the output

We need \(\partial L/\partial\theta\) for every weight. One backward sweep, reusing each layer’s result.

Output layer. Sigmoid + cross-entropy gives a small miracle: \[\delta^{(2)} \equiv \frac{\partial L}{\partial z^{(2)}} = p - y\] How wrong, with a sign. Example: \(\delta^{(2)} = 0.5973 - 1 = \mathbf{-0.4027}\).

Then, since \(z^{(2)} = \sum_h W^{(2)}_h a^{(1)}_h + b^{(2)}\): \[\frac{\partial L}{\partial W^{(2)}_h} = \delta^{(2)} a^{(1)}_h, \qquad \frac{\partial L}{\partial b^{(2)}} = \delta^{(2)}\]

Example: \(\partial L/\partial\mathbf{W}^{(2)} = -0.4027\times(0.6044,\ 0.1974) = (-0.2434,\ -0.0795)\).

Step 2: pass the blame back through the hidden layer

How much did each hidden activation contribute to the error? \[\frac{\partial L}{\partial a^{(1)}_h} = \delta^{(2)}\,W^{(2)}_h \;\Rightarrow\; (-0.4027)(0.7,\ -0.4) = (-0.2819,\ 0.1611)\]

Through the activation (\(a = \tanh z\), so multiply by \(1 - a^2\)): \[\delta^{(1)}_h = \frac{\partial L}{\partial a^{(1)}_h}\,(1-(a^{(1)}_h)^2) \;\Rightarrow\; (-0.2819)(0.6347),\ (0.1611)(0.9610) = (-0.1789,\ 0.1548)\]

Input weights (\(z^{(1)}_h = \sum_j W^{(1)}_{jh}x_j + b^{(1)}_h\)): \[\frac{\partial L}{\partial W^{(1)}_{jh}} = \delta^{(1)}_h\,x_j \;\Rightarrow\; \begin{pmatrix}1.0\\0.5\end{pmatrix}(-0.1789,\ 0.1548) = \begin{pmatrix}-0.1789 & 0.1548\\ -0.0895 & 0.0774\end{pmatrix}\]

Step 3: one gradient-descent step, η = 0.5

\[\mathbf{W}^{(1)} \to \begin{pmatrix}0.5895 & -0.3774\\ 0.2447 & 0.7613\end{pmatrix},\quad \mathbf{b}^{(1)} \to (0.1895,\ 0.0226),\quad \mathbf{W}^{(2)} \to (0.8217,\ -0.3603),\quad b^{(2)} \to 0.2514\]

Forward pass again with the new weights: \(\mathbf{p = 0.6966}\), loss \(0.3615\) (was 0.5154).

The network moved toward the right answer for this person. Average the gradients over all \(n\) people, repeat a few thousand times, and it has learned. That is all learning means here: the numbers in \(\mathbf{W}\) changed.

Frameworks (torch, TensorFlow, JAX) derive the backward pass for any architecture automatically — automatic differentiation. You write the forward pass. The maths does not change.

The same thing, in matrix form (Tutorial 7 Part B)

fw  <- forward(X, W1, b1, W2, b2); P <- fw$P; A1 <- fw$A1
dZ2 <- (P - y) / n                   # delta at the output          (n x 1)
dW2 <- t(A1) %*% dZ2                 # blame for hidden->output weights   (H x 1)
dA1 <- dZ2 %*% t(W2)                 # pass the blame back through W2     (n x H)
dZ1 <- dA1 * (1 - A1^2)              # through the tanh                   (n x H)
dW1 <- t(X) %*% dZ1                  # blame for input->hidden weights    (p x H)
W1 <- W1 - lr * dW1;  b1 <- b1 - lr * colSums(dZ1)
W2 <- W2 - lr * dW2;  b2 <- b2 - lr * sum(dZ2)

Five lines of backpropagation, two of gradient descent. Run 500 times → the ring.

Making training work

  • Initialisation: small random weights, never all zero (identical units would get identical gradients and never differentiate). Xavier/Glorot (tanh) and He (ReLU) scale the randomness to the fan-in. Different seeds → slightly different networks; report it.
  • Vanishing / exploding gradients: each backward step multiplies by a weight and an activation derivative; products of many small numbers → 0, of large ones → ∞. Fixes: ReLU, good init, gradient clipping, batch normalisation, residual connections.
  • Scale the inputs: gradient descent on hh_income in ringgit and age in years spends all its steps on income. step_normalize() — not optional.

3 · Keeping it honest

Networks overfit by default

1,411 weights on ~3,200 people per fold — about 2 people per parameter; a classical statistician wants 10–20 events per parameter. Left alone, training loss → 0, validation AUC falls, probabilities pile up at 0 and 1.

Brake Mechanism parsnip / brulee
weight decay (L2) add \(\lambda\sum\theta^2\) to the loss → every step also shrinks the weights; the network’s ridge regression penalty
dropout silence a random fraction of units on each training step; forces redundancy; ≈ an ensemble dropout (brulee)
early stopping stop when a validation slice stops improving stop_iter, validation
smaller architecture fewer units / layers hidden_units
batch normalisation stabilises, mildly regularises brulee option
data augmentation more (perturbed) examples images, audio

Always early-stop when you can. Weight decay or dropout, not both (brulee). Tune width and decay together.

Architecture choices for tabular data

  • Width: 8–64 units for a few thousand rows. Depth: one hidden layer is usually enough; two (32 → 16) occasionally helps; more rarely does.
  • Activation: ReLU for depth; tanh/sigmoid fine for one small layer.
  • Output: parsnip sets it from set_mode() — sigmoid/softmax/identity.
  • What to tune, in order: learning rate (if not L-BFGS) → width → decay/dropout → epochs (early stopping) → batch size → depth.

Universal approximation says a wide-enough single layer can represent any continuous function. It does not say gradient descent will find it, or that 3,200 people will identify it. Depth gets there with far fewer parameters.

Tuning a network is tuning

nn_tune_wf <- workflow(dm_rec, mlp(hidden_units = tune(), penalty = tune(), epochs = 200) |>
                         set_engine("nnet", MaxNWts = 10000) |> set_mode("classification"))
nn_params <- extract_parameter_set_dials(nn_tune_wf) |>
  update(hidden_units = hidden_units(range = c(2L, 24L)), penalty = penalty(range = c(-4, -0.5)))

nn_race <- tune_race_anova(nn_tune_wf, dm_folds, param_info = nn_params, grid = 16, metrics = metric_set(roc_auc, brier_class))
nn_last <- last_fit(finalize_workflow(nn_tune_wf, select_best(nn_race, metric = "roc_auc")), dm_split)
  • Width and weight decay are the two that matter for one layer; learning rate and epochs join for deeper ones.
  • Expect more run-to-run variability than trees (random initialisation). Repeated CV earns its keep.
  • Explain it with kernelshap() (no TreeSHAP for a network) and this morning’s shapviz plots. If network and trees agree on the structure, both are more believable.

5 · When not to use one

The evidence on tabular data

Study Finding
Shwartz-Ziv & Armon 2022, Information Fusion XGBoost beat the deep tabular models on the very datasets those models were published with
Grinsztajn, Oyallon & Varoquaux 2022, NeurIPS 45 datasets: tuned GBMs win on medium-sized tabular data; nets struggle with uninformative features and non-smooth targets
McElfresh et al. 2023, NeurIPS 176 datasets: for most, the gap is smaller than the gain from tuning; nets win on some large, smooth problems
Christodoulou et al. 2019, J Clin Epidemiol no benefit of ML over logistic regression across 71 clinical prediction studies, after bias

On a 5,000-row survey a well-regularised network ties boosted trees and logistic regression — and costs more compute, more tuning, more variance and less interpretability. Tutorial 7 shows exactly that. It is a finding, not a failure.

Where neural networks earn their keep

Data Architecture Health examples
Images CNNs, vision transformers retinopathy, chest X-ray, pathology, dermatology, radiology triage
Signals / waveforms 1-D CNN, RNN/LSTM, transformers ECG, EEG, PPG, continuous monitoring
Text transformers (BERT, GPT family) clinical notes, coding, referral triage, literature
Event sequences RNN, transformers EHR trajectories, next-visit prediction
Very large tabular (10⁶+ rows) MLP, TabNet, FT-Transformer claims, national registries — sometimes
Multimodal fused encoders image + report + labs

Common thread: inputs are raw and high-dimensional; the useful features (an edge, a QRS complex, a phrase) must be learned. Tabular data arrives already feature-engineered — which is why trees do fine.

Convolution, recurrence, attention — one slide each

CNN — a 3×3 filter slides across the image and fires where it matches a pattern; layers of filters build edges → textures → parts → objects; pooling shrinks and adds translation invariance. Transfer learning: start from a net trained on millions of natural images, retrain the last layers on your 2,000 fundus photos.

RNN / LSTM — process a sequence step by step, carrying a hidden state (memory); LSTM gates decide what to keep and forget. ECG, vital-sign streams, early EHR-sequence models. Largely superseded by …

Transformer — every position looks at every other and learns where to look (attention); no recurrence, massively parallel. The basis of BERT/GPT, modern vision models, and the medical foundation models now arriving.

How deep learning fails in health

  • Shortcut learning: pneumonia classifiers that read the portable-X-ray marker; skin-cancer models that detect the dermatologist’s ruler; COVID CXR models that learned the hospital (DeGrave et al. 2021).
  • Dataset shift: a new scanner, population or protocol — performance collapses silently.
  • Over-confidence: badly calibrated out of the box (Guo et al. 2017) → temperature scaling / Platt before deployment.
  • Data and label hunger; label noise propagates.
  • Reproducibility: seeds, GPU non-determinism, undocumented pre-processing.
  • Equity: under-performance on under-represented groups unless measured.

Same medicine as the rest of the workshop: leak-free splits by patient, honest resampling, calibration, subgroup checks, explanations used as audits.
